# 研究架构与迁移

仓库有两条独立依赖链：Python `latex_sft` 负责研究，Node `qwen-latex-cli` 负责通过 Ollama 使用模型。两者只共享版本化提示词资源；npm 包不包含 Python、数据或权重。

## 模块边界

| Python 模块 | 职责 |
|---|---|
| `core` | 公式 AST、保真比较、排版和输出协议；不启动推理 |
| `data` | 生成、记录 IO、审查、质量规则、结构连接和集合分配 |
| `evaluation` | 保存预测的评分、指标、诊断及报告 |
| `experiments` | 来源验证、训练投影、直接 CLI 执行、checkpoint 选择 |

保真评分保留自由变量、常量、作用域与算子类型；结构分组可以抽象变量用于防泄漏，两者不共用等价判定规则。连通分量内核共享，但新数据分配与已冻结集合的冲突隔离是不同策略，不相互替代。

训练调用 LLaMA-Factory；外部数学评测继续直接使用 lm_eval，不增加远端进程调度框架。默认研究版本为 reviewed v5.2。数据/配置/报告按现有路径保留，避免破坏外部引用。旧 `python -m training.*` 和生成工具路径由薄兼容层转入新模块；旧命令的默认版本仍按旧接口处理，因此复现时要显式指定版本。

## 历史协议不是当前代码

迁移前基线 `a082730ef3657571e70cf4720efbb0958ded6b57` 的源码与配置逐字节保存在 `archive/protocols/a082730`，原路径/内容哈希映射用于解释旧 manifest。历史标签、人工审查、预测和导出哈希保持不变。

验证器将历史来源与当前执行协议分开验证：旧导出检查原来源快照及审查/数据文件，新执行记录绑定当前包源码和提示词。不能改旧哈希来适配新路径，也不能声称新实现就是原实验执行代码。快照、映射或标签被修改时应验证失败。

历史 v5 产物若本来就与其绑定源码不匹配，不通过迁移绕过检查；应使用对应历史提交与完整原产物复现。当前默认入口为经过审查的 v5.2。

## 用户 CLI

`packages/cli` 使用 Node 原生 fetch 调用用户自己的 Ollama OpenAI 兼容接口。Python 提示词资源是唯一维护来源，npm 打包时复制并校验。CLI 不承担 AST 评分、不下载模型、不管理 Ollama 或 GPU 生命周期。旧桌面位于 `archive/desktop`，不进入任何安装包。
